# Pipeline Invariants

Streaming compilation, derived file-edge truth, and incremental
re-analyze. Memory-safe by default; full retention only opted into by
the MCP server.

## Streaming Compilation Architecture (v0.3.0)

- **INV-STREAM-001**: `ModuleCompilationBuilder.ProcessInOrder` compiles one module at a time in topological order. After extraction, `Emit()` → `MetadataReference.CreateFromImage()` downgrades the full compilation (~200MB) to a lightweight PE reference (~10-100KB). Peak memory: O(1 compilation), not O(N).
- **INV-STREAM-002**: `SharedMetadataReferenceCache` deduplicates NuGet MetadataReferences across modules. One instance per `AnalyzeWorkspace` call.
- **INV-STREAM-003**: `AnalysisConfig.RetainCompilations` controls mode. `false` (default, CLI) = streaming/memory-safe. `true` (MCP server) = retained for write-side tools.
- **INV-STREAM-004**: Unity csproj support: if `<Compile Include>` items exist (old-format), use them. If absent (SDK-style), scan filesystem.
- **INV-STREAM-005**: `GraphBuilder.Build()` deduplicates ALL edges by `(sourceId, targetId, kind)`. Partial classes emit duplicate edges. The builder is the authoritative dedup boundary.

## Derived File Edges

- **INV-FILE-EDGE-001**: `GraphBuilder.Build()` derives file-level `References` edges from symbol-level edges. For each non-Contains edge between symbols in different files, a `file:X → file:Y References` edge is emitted with an `edgeCount` property. Evidence: `Inferred`, adapter: `GraphBuilder`. File edges are derived truth. Not primary.

## Incremental Re-Analyze

- **INV-SNAPSHOT-ATOMIC-PUBLISH-001. Full and incremental candidates cannot publish adapter, workspace-path, scope, rules, generation, graph, analysis, source-control evidence, or semantic ports before graph extraction, validation, rule analysis, and compilation-service construction succeed.** `WorkspaceSnapshot` is the immutable Application publication containing graph, analysis, capability, workspace context, analyzed timestamp, generation, source-control evidence captured for that publication, and the complete compilation-port triplet. `GraphSession` wraps that value with the exact Roslyn adapter, rules path, and exclude scope in one immutable committed host state. The full path constructs a fresh candidate only after live identity preflight fails to match the current publication; incremental and stale-refresh paths deep-fork every mutable extraction cache, compilation dictionary, and module-dependency collection. Only one reference exchange publishes the complete candidate, while an incremental no-op may replace only the host wrapper to retain harmless timestamp/content-hash cache state without advancing or replacing the Application snapshot. If a full request resolves to the same `WorkspaceAnalysisIdentity` already committed, the response reuses the current publication instead of creating a duplicate generation, and reports `publication.action:"reusedCurrent"`. Compilation services are constructed after rule analysis, and partial service triplets are rejected. A pre-commit failure therefore leaves the prior snapshot reference—and every field reachable from it—consistent and retryable. Pinned by `GraphSessionPublicationTests` full/incremental snapshot-reference rollback assertions, exact-identity reuse coverage, and `UseCaseTests.WorkspaceSnapshot_Create_RejectsPartialCompilationPortPublication`.

- **INV-SNAPSHOT-LEASE-001. Replacing a committed snapshot retires it immediately but disposes its semantic ports only after the final read lease releases.** `WorkspaceSnapshot.TryAcquireLease` atomically refuses retirement races, counts successful pins, and lets existing readers finish against one immutable generation. `GraphSessionGate` binds a lease to the request execution context, so every session property in that call resolves through the same committed host/Application state while a writer builds and publishes the next generation concurrently. Writers remain single-flight. An incremental no-op shares the same snapshot lifetime while replacing only the adapter-cache wrapper; a later real publication still waits for leases acquired through either wrapper. Pinned by `GraphSessionGateTests.Read_PinsOneSnapshotWhileWriterPublishesNextGeneration`, non-blocking reader/writer tests, writer-serialization coverage, and `UseCaseTests.WorkspaceSession_Clear_ResetsAllState` deferred-disposal assertions.

- **INV-SNAPSHOT-IDENTITY-001. Every loaded committed `WorkspaceSnapshot` owns one opaque globally unique `SnapshotId`; identity is preserved only while the same analysis publication is preserved.** `SnapshotId` is a Domain value object with the wire form `snap_<32 lowercase hex digits>` and an explicit empty sentinel for an unloaded session. Full analyze, changed incremental analyze, fallback-to-full, and later reload after clear create a new id only when they publish a different `WorkspaceAnalysisIdentity`; exact duplicate full analyzes reuse the current publication and therefore its id. Incremental no-op also reuses the exact Application snapshot and therefore its id; attaching semantic ports to the same `WorkspaceSession` publication preserves the id; rejected or failed candidates leave it unchanged. This identity is intentionally not a duplicate content/spec hash: `AnalysisKey` owns equality and coalescing, while `SnapshotId` answers which exact publication a read used and cannot collide merely because another daemon restarted at the same generation. The id flows through `EnvelopeContext` to every successful tool envelope and through capability session status; analyze responses additionally expose `publication.action`, `publication.snapshotId`, and `publication.analysisGeneration` so retries can distinguish a fresh publication from reuse. Adapter-capability downgrade and unregistered-tool branches must preserve it. Pinned by `UseCaseTests`, `ResponseEnvelopeTests`, `ResponseEnvelopeWireShapeContractTests`, `GraphSessionPublicationTests`, and shared-process generation propagation/restart coverage.

- **INV-ANALYZE-FINGERPRINT-001. `WorkspaceAnalysisIdentity` is the single immutable authority for analysis equality and provenance: `WorkspaceKey + AnalysisSpec = BaseKey`; `BaseKey + SourceFingerprint = AnalysisKey`.** Every hash uses the Domain-owned length-framed, domain-separated SHA-256 `ContentFingerprint` wire contract. `AnalysisSpec` preserves define-profile order because the first profile owns retained compilations, normalizes exclude-glob order/case because the matcher is order/case insensitive, distinguishes graph-only from retained-semantic mode, and owns the canonical rule-content fingerprint. `SourceFingerprint` deterministically folds the exact source-content cache plus discovery descriptors (`.sln` / `.csproj`), Unity asmdefs, Unity package visibility descriptors/inventory, external references, and source-generator binaries retained by the C# adapter; git commit and mtimes are never equality authority. Physical sources mounted by an adapter use the same logical workspace path as graph and incremental evidence, so machine-local package storage paths do not create a second identity vocabulary (`INV-WORKSPACE-SOURCE-PATH-001`). `SnapshotId` remains a distinct exact-publication identity and MUST NOT be derived from `AnalysisKey`. Analyze responses project the committed identity object and never rebuild keys from parallel wire fields. Pinned by `WorkspaceAnalysisIdentityTests`, `GraphSessionAnalysisIdentityTests`, and `PackageSourceVisibilityTests.IncrementalAnalyze_PackageVisibilityInputChange_PublishesNewIdentity`.

- **INV-ANALYSIS-IDENTITY-PROJECTION-001. Every bounded public projection of committed analysis identity derives from one Domain-owned `WorkspaceAnalysisDescriptor`; hosts and connectors never rebuild parallel anonymous key sets.** The descriptor is a stable, source-path-free projection of `WorkspaceAnalysisIdentity` containing workspace/base/analysis keys, spec/source/descriptor fingerprints and counts, rule fingerprint, retention/descriptor policy, profiles, and excludes. Analyze results, every successful response envelope, read batches, and precondition mismatches reuse `WorkspaceAnalysisDescriptor.From(identity)`; later snapshot inventory must reuse the same descriptor rather than create another projection. Adding or changing an identity field therefore has one projection seam and one wire-shape ratchet instead of independently drifting response types. Pinned by `ResponseEnvelopeWireShapeContractTests`, `ToolHandlerTests.Handle_ReadPrecondition_AcceptsCurrentSnapshotThenRejectsAfterRefresh`, and analyze identity coverage in `GraphSessionAnalysisIdentityTests`.

- **INV-ANALYZE-RULE-REFRESH-001. Rule identity is content-authoritative and refresh-aware.** One `AnalysisRuleSetResolver` returns the parsed `ArchitectureRule[]` together with the `RuleSetIdentity` produced from that exact canonical array; file I/O, built-in lookup, relative-path resolution, and fingerprinting cannot diverge. An incremental request that omits `rulesPath` re-resolves the committed rule source, so editing a rules file with unchanged C# cannot return `incremental-noop` with stale violations. If source/descriptor/spec identity is otherwise unchanged, Lifeblood reruns only the stateless rule pipeline, publishes a new generation / `SnapshotId` / `AnalysisKey`, and leaves the graph plus retained semantic services shared. Invalid refreshed rules fail before publication and preserve the exact prior snapshot. Pinned by `GraphSessionAnalysisIdentityTests` and `GraphSessionPublicationTests`.

- **INV-SNAPSHOT-SEMANTIC-SHARE-001. Publications derived over the same immutable graph share one reference-counted compilation-service bundle instead of rebuilding or double-owning Roslyn ports.** `WorkspaceSnapshot.DeriveAnalysis` increments the bundle reference before constructing the candidate. Retirement releases one reference only after that snapshot's final read lease; the host/executor/refactoring triplet is disposed exactly once after every publication and reader releases it. This is the rule-only/metadata-only refresh seam and must never be used when the graph or retained compilation set changed. Pinned by `GraphSessionAnalysisIdentityTests` plus the existing deferred-disposal coverage in `UseCaseTests` and `GraphSessionGateTests`.

- **INV-SNAPSHOT-CATALOG-BOUND-001. Historical publication retention is hard-bounded and graph-only; it cannot extend a semantic-service lifetime or create a second Roslyn base.** Application owns `WorkspaceSnapshotCatalog`, its limit/age policy, pin/name semantics, LRU eviction, and lease-safe retirement. A retained replica reuses the immutable graph, analysis, capability, context, identity, generation, and exact `SnapshotId`, but publishes `WorkspaceCapability.None` and no compilation-service bundle. Pinned entries consume the same configured slots as unpinned entries; when every slot is pinned, automatic rollover is refused, counted, and never widens the hard bound. Unpinned entries expire by age or LRU, explicit eviction denies new leases while issued leases finish, cross-workspace publication clears history, and the environment edge may configure 0–16 entries without weakening the Application maximum. Pinned by `WorkspaceSnapshotCatalogTests`, `UseCaseTests.WorkspaceSnapshot_GraphOnlyReplica_PreservesPublicationWithoutRetainingSemanticServices`, and `GraphSessionSnapshotCatalogTests`.

- **INV-ANALYZE-COALESCE-001. Exactly equal in-flight analyses share one candidate operation, while any identity or execution-policy difference remains isolated.** `GraphSession.PrepareAnalysis` consumes the C# adapter's `IWorkspaceInputFingerprintProvider` preflight receipt and builds the same `WorkspaceAnalysisIdentity` later required at publication; source drift between preflight and candidate completion returns a retryable `analysis-input-changed` failure and cannot publish. `AnalysisRequestCoordinator` keys work by `AnalysisKey` plus execution-policy fingerprint, closes entries before completion, removes them before publishing success/failure, gives every waiter one request id and final waiter count, and cancels the shared token only after every waiter leaves. Tool responses clone the shared result before adding per-waiter `coalesced` metadata. Failures fan out without poisoning retry. Transport-level MCP cancellation is a separate lifecycle concern and must feed this coordinator rather than create another cancellation registry. Pinned by `AnalysisRequestCoordinatorTests`, `GraphSessionAnalysisIdentityTests`, `AnalyzeWireShapeTests`, and `ToolHandlerTests.Handle_Analyze_LoadsGraph`.

- **INV-INCR-001**: Incremental re-analyze (`lifeblood_analyze` with `incremental: true`) only recompiles modules whose source content changed since the last analysis. Per-file extraction results are cached in `AnalysisSnapshot`. Filesystem mtimes are a cheap prefilter only; source content hashes decide whether a touched file actually re-extracts. v1 limitation: does not cascade to dependent modules when API surface changes.

- **INV-INCREMENTAL-CONTENT-HASH-001. Incremental source-file change detection is content-authoritative, not mtime-authoritative.** `AnalysisSnapshot` stores a source content hash for every tracked source file alongside the existing extraction cache. Incremental analyze still uses mtimes to find touched candidates cheaply, but a file whose mtime changed and whose content hash is unchanged MUST return `mode:"incremental-noop"` without replacing graph slices. Responses surface both counters: `mtimeTouchedSourceFiles` counts files whose timestamp suggested work, and `contentChangedSourceFiles` counts files whose content hash actually changed. `changedSourceFiles` remains the re-extracted source-file count and therefore matches the content-changed count for normal C# source updates. This closes the mtime-only touch class where editor save/format churn invalidated otherwise stable graphs. Pinned by `IncrementalAnalyzeTests` content-hash and mtime-only no-op cases plus MCP wire-shape coverage on the counters.

- **INV-ANALYZE-AUTHORITATIVE-CHANGESET-001. `lifeblood_analyze authoritativeChangedFiles` may narrow the incremental source scan but must not suppress descriptor or scope drift checks.** When an editor, IDE, or filesystem watcher knows the exact changed-file set, the MCP edge binds it as project-relative or absolute paths and the C# adapter intersects incremental source candidates with that set before hashing. The hint is advisory for source-file scanning only: csproj/asmdef descriptor drift, module-set drift, read-only compilation-state gaps, and `excludePaths` analysis-scope drift are still evaluated independently and can still reject or widen according to `allowFullFallback`. Empty or unknown paths are normalized and ignored rather than treated as deletion authority. Pinned by `ToolArgumentContractTests` binding coverage and `IncrementalAnalyzeTests` authoritative-changed-file narrowing cases.

- **INV-ANALYZE-ACCEPTED-CHANGE-001. One immutable Application receipt is the authority for every source path and count accepted by an incremental analysis.** `AcceptedChangeSet` owns sorted, unique, project-relative POSIX workspace identities for reanalyzed, mtime-touched, content-changed, descriptor-forced, and deleted sources plus the scan mode (`FilesystemPrefilter`, `AuthoritativeChangedSet`, or `FullFallback`). Adapter-mounted sources such as an external Unity `file:` package must first project through the adapter's source-path map to `Packages/{name}/...`; the Application contract continues to reject rooted and traversal paths. Content-changed and descriptor-forced paths must be reanalyzed; deleted and reanalyzed sets must be disjoint; legacy counts are derived projections and cannot drift from path evidence. A full fallback truthfully reports all tracked sources as reanalyzed but MUST NOT claim that every source mtime or content changed when those causes were not measured. The MCP edge projects the same object as `acceptedChanges`: `summary` is the default and returns causes/interpretation/counts without paths; `detail` returns one sorted union of per-path boolean facts, bounded by `changeReceiptLimit` (default 50, hard-clamped 1–200) with complete evidence/returned/omitted counts and an explicit truncation flag. The projection must spell out `changedSourceFilesMeaning:"reanalyzedOrDeleted"` and a `contentChangeStatus` so clients do not treat fallback reanalysis as source-content churn. An explicitly empty `authoritativeChangedFiles` remains distinct from omission, and scan mode plus normalized receipt projection participate in the execution-policy fingerprint so incompatible requests never coalesce into the wrong response. No repeated per-cause path arrays or parallel count authority is allowed. Pinned by `AcceptedChangeSetTests`, `IncrementalAnalyzeTests`, `AnalyzeWireShapeTests`, `PackageSourceVisibilityTests.FreshIncrementalFallback_ExternalFilePackageUsesOneLogicalSourceIdentity`, `GraphSessionAnalysisIdentityTests`, `ToolArgumentContractTests`, and the `lifeblood_analyze` schema snapshot.

- **INV-INCREMENTAL-XREF-001. Cross-module edges survive incremental analyze.** After every successful `ModuleCompilationBuilder.ProcessInOrder` call, the snapshot-owned `AnalysisSnapshot.DowngradedRefs` dictionary contains exactly one entry per module the analyzer successfully compiled — including unchanged modules carried forward from prior full analyzes with their stale-but-still-valid PE metadata. The two paths agree on the contract: full analyze CLEARS `DowngradedRefs` before processing every module from scratch; incremental analyze threads the snapshot-owned carry as a SEED into `ProcessInOrder` and merges the working dict back at end-of-call. Without this, incremental analyze called `ProcessInOrder` with only the `modulesToRecompile` subset, so unchanged dependencies had no metadata reference, every cross-module symbol bound to a Roslyn error symbol, and the corresponding edges were silently dropped by `GraphBuilder`'s dangling-edge filter — a silent-data-loss class causing false-positive dead-code findings on any symbol consumed only from unchanged modules. **Acceptance criterion (now pinned):** two consecutive `analyze` calls on the same source tree — `incremental: true` then `incremental: false` — must produce identical `summary.edges`. Pinned by `IncrementalAnalyzeTests.IncrementalAnalyze_CrossModuleEdges_IdenticalAfterContentlessTouch` + `IncrementalAnalyze_CrossModuleEdges_PreservedAfterContentChangeInDependent`. Closes `LB-BUG-020` (incremental edge drop, field-report 2026-05-11).

- **INV-JSON-IMPORT-BOM-001. JSON imports accept any standard BOM, not just bare UTF-8.** `System.Text.Json.JsonSerializer.Deserialize<T>(Stream)` requires UTF-8 and throws an unhandled exception on UTF-16-LE-BOM, UTF-16-BE-BOM, UTF-8-BOM, etc. The README-documented `lifeblood export --project ... > graph.json` pattern on Windows PowerShell writes UTF-16-LE-with-BOM by default; passing the resulting file straight to `lifeblood analyze --graph graph.json` (or via the MCP `graphPath` arg) crashed pre-fix. Every Stream-to-JSON-deserialize path MUST route through `StreamReader(stream, Encoding.UTF8, detectEncodingFromByteOrderMarks: true)` and pass the resulting string to the JSON deserializer; the StreamReader auto-detects all five standard BOMs (UTF-8, UTF-8-BOM, UTF-16-LE-BOM, UTF-16-BE-BOM, UTF-32 variants) and defaults to UTF-8 when no BOM is present. Pinned by `JsonRoundTripTests.ImportDocument_AcceptsAllStandardBomEncodings` (4-case theory) plus end-to-end CLI verification via a real on-disk transcoded file. Enforcement site: `JsonGraphImporter.ImportDocument`. Other JSON-from-Stream callsites (`RulePacks.ResolveBuiltIn` reads embedded resources baked into the assembly as UTF-8 by the build, so it is not user-facing and not vulnerable to PowerShell-redirect drift; `ProcessIsolatedCodeExecutor`, `ScriptHost.Program`, and `Server.Mcp.Program` deserialize from STRINGS, not Streams, and are not vulnerable). When adding a new Stream-to-JSON-deserialize site, pair it with a BOM round-trip ratchet.

- **INV-MCP-STDIO-UTF8-001. MCP / JSON-RPC stdio ports MUST be pinned to UTF-8.** The MCP protocol mandates UTF-8 over stdio. The host process's `Console.InputEncoding` / `Console.OutputEncoding` defaults are OS-dependent — on Windows they are typically a non-UTF-8 ANSI codepage (e.g. Windows-1252, Shift-JIS), which silently mangles multi-byte characters in JSON args (Unicode identifiers, accented characters in search queries) and JSON responses. Every MCP-server composition root MUST set `Console.InputEncoding = Console.OutputEncoding = Encoding.UTF8` before any `Console.In.Read*` / `Console.Out.Write*` call. Enforcement site: `Server.Mcp.Program.Main` (top of the method, before the dispatcher loop). Defensive — no test failure has been observed, but the broader bug class is identical to `INV-JSON-IMPORT-BOM-001`: a transport that mandates UTF-8 must explicitly pin UTF-8 rather than trust the host's defaults.

- **INV-ANALYZE-STRUCTURED-FAILURE-001. The analyze pipeline never lets a raw fault escape — it wraps it with phase/module/file/profile context.** `RoslynWorkspaceAnalyzer.AnalyzeWorkspace` maintains a coarse progress cursor (phase ∈ {discovery, compilation, module-edges, graph-build}, current module, current file, current profile, reached-compilation flag) updated at every phase boundary, inside the `onModuleProgress` callback, and per syntax tree. Any UNEXPECTED exception is caught at the method boundary and re-thrown as a `WorkspaceAnalysisException` carrying that cursor + the inner exception; an already-structured `WorkspaceAnalysisException` re-throws unchanged, and deliberate caller-input validation (`ArgumentException`, e.g. an unknown define-profile name) propagates as its typed contract rather than being masked as a pipeline fault. The MCP handler (`ToolHandler.HandleAnalyze`) catches the typed exception and serializes `{phase, module, filePath, profile, failedBeforeCompilation, exceptionType, message}` instead of letting the dispatcher emit a bare `"Error: Object reference not set to an instance of an object."`. Motivation: agents use full analyze as the trust reset; an opaque collapse there (observed as a NullReference after Unity asset-import churn, `LB-INBOX-012`) forces a blind fall back to grep/IDE with no idea which phase is unsafe. The exception type is language-agnostic so any `IWorkspaceAnalyzer` reuses it. Pinned by `WorkspaceAnalysisFailureTests.AnalyzeWorkspace_PipelineFault_ThrowsStructuredException_WithPhaseContext`.

- **INV-ANALYZE-FALLBACK-001. Scope-widening is a caller policy, not an adapter decision.** When the adapter detects drift it cannot honor cheaply (no prior cache, module set changed since the snapshot, project descriptor edited, analysis-scope options changed, or retained compilation state unavailable after a read-only analyze), the response shape is determined by the caller's `AnalysisConfig.AllowFullFallback` flag. **Default `false`** (fail-loud): the adapter returns `IncrementalAnalyzeResult { Mode = Rejected, Graph = null, Reason = ..., Detail = ... }` - no work done, caller decides next step. **Opt-in `true`**: the adapter widens to a full re-analyze and returns `Mode = FullFallback, Graph = ..., Reason = ...` so the result lands AND the cache miss stays visible. The reason taxonomy is adapter-agnostic - `NoPriorAnalysis`, `ModuleSetChanged`, `ModuleDescriptorChanged`, `AnalysisScopeChanged`, `CompilationStateUnavailable` - so future Python / TypeScript / etc. adapters reuse the same shape; the adapter-specific descriptor kind (`asmdef`, `csproj`, `pyproject.toml`), scope kind (`excludePaths`), or retained-state detail lives in `Detail`. Internal best-effort callers like `GraphSession.MaybeRefreshIfStale` deliberately set `AllowFullFallback = true` because their contract is "make state fresh"; user-facing callers route the user's own flag through unchanged. At the adapter boundary `NoPriorAnalysis` is always rejected because no project root exists without a snapshot. At the MCP orchestration boundary the request already supplies `projectPath`, so `allowFullFallback:true` may perform a full first analysis while preserving `requestedMode:"incremental"`, `fallbackReason:"noPriorAnalysis"`, and a full-fallback accepted-change receipt. Wire `mode` reports what the adapter DID (`full` / `incremental` / `incremental-noop` / `rejected`); `requestedMode` separately reports what the caller ASKED (`full` / `incremental`); `fallbackReason` + `fallbackDetail` populate whenever the cheap path could not be honored cleanly; rejection responses additionally carry `canRetryFull: true` and `suggestedRetry: { incremental: true, allowFullFallback: true }`. Rejection is a normal structured result, not a transport/tool error. A fallback must preserve the request's effective define-profile sequence through analysis, summary/per-profile counts, retained compilation metadata, and canonical `AnalysisSpec`; widening cost may never narrow preprocessor scope. Pinned by `IncrementalAnalyzeTests` and `AnalyzeWireShapeTests` across adapter rejection, first-call orchestration, scope drift, module drift, and read-only recovery, plus `ToolHandlerTests.Handle_Analyze_MultiProfileDescriptorFallbackPreservesRequestedProfiles` for the exact Editor+Player asmdef-drift MCP regression.

- **INV-READONLY-RECOVERY-001. A read-only MCP analyze must not leave the session in a crash-prone half-retained state.** `readOnly:true` intentionally streams and releases Roslyn compilations so write-side tools are unavailable. If the next call requests incremental retained analysis without a retained compilation snapshot, `lifeblood_analyze` MUST return a structured `mode:"rejected"` response with `fallbackReason:"compilationStateUnavailable"`, `canRetryFull:true`, and the same `suggestedRetry` shape as other fallback cases. With `allowFullFallback:true`, the server MUST run a full retained analyze and rebuild the `RoslynSemanticView` instead of trying to incrementally reuse missing compilation state. Pinned by `AnalyzeWireShapeTests` and direct stdio smoke coverage against the rebuilt MCP server.

- **INV-ANALYZE-EXCLUDEPATHS-001. `lifeblood_analyze excludePaths` removes files from analysis scope before Roslyn compilation and changing that set is incremental scope drift.** The MCP edge accepts project-relative POSIX path globs with the shared `PathGlobMatcher` grammar (`*` = any run including `/`, `?` = one character, full-path case-insensitive match). `ModuleCompilationBuilder` applies the compiled glob set before parsing syntax trees, so excluded files never enter Roslyn, extraction, graph validation, diagnostics, or retained compilations. `AnalysisSnapshot` records the normalized exclude set; incremental analyze compares the requested set to the retained set and returns `FallbackReason.AnalysisScopeChanged` / wire `fallbackReason:"analysisScopeChanged"` unless `allowFullFallback:true` permits a full re-analyze. `GraphSession` remembers the active exclude set for stale auto-refresh and clears it on JSON graph import. Pinned by `AnalyzeWireShapeTests.Load_FullAnalyze_ExcludePaths_DropsMatchingSourceFromGraph`, `Load_IncrementalWithChangedExcludePaths_RejectsWithAnalysisScopeChanged`, `CsprojCompilationFactsTests.Compilation_ExcludePathGlobs_DropsMatchingSourceBeforeGraphExtraction`, `ToolArgumentContractTests.BindAnalyze_ExcludePaths_*`, and the `lifeblood_analyze` schema snapshot. Closes the analyze-scope half of `LB-INTAKE-20260601-004`.
