## Dead-Code Analysis (v0.6.3, major fix v0.6.4)

- **INV-DEADCODE-001. `lifeblood_dead_code` walks the graph for symbols with zero incoming non-Contains edges. Every response carries `status` + `warning` fields.** The analyzer checks `graph.GetIncomingEdgeIndexes(sym.Id)` and also checks outgoing `Implements` edges as proof of liveness (a method implementing an interface is reachable through the interface). Self-analysis tail after the post-v0.6.4 extractor pass: ~7 findings (from 150 pre-v0.6.4), all in the known-structural-limitation set below.

  **Closed false-positive classes** (v0.6.4 + post-v0.6.4 extractor pass). Each maps to one or more extractor changes in `RoslynEdgeExtractor`:
  - **Interface dispatch.** `ExtractInheritanceEdges` emits method-level `Implements` edges via `FindImplementationForInterfaceMember` + `AllInterfaces`. Dead-code analyzer checks outgoing `Implements` as proof of liveness.
  - **Member access granularity.** `ExtractMemberAccessEdge` + `ExtractReferenceEdge` emit both type-level and symbol-level `References` edges for properties/fields/method-groups via `EmitSymbolLevelEdge` shared helper. Covers bare field identifiers and method-group references (`new Lazy<>(Load)`, `event += Handler`).
  - **Null-conditional property access.** `MemberBindingExpressionSyntax` handler emits type-level + symbol-level edges for `obj?.Property`.
  - **Lambda / local-function context.** `FindContainingMethodOrLocal` skips lambda and local-function syntax nodes. Calls inside `.Select(x => Foo(x))` attribute to the enclosing named method.
  - **Implicit global usings.** `ModuleInfo.ImplicitUsings` discovered from csproj; `ModuleCompilationBuilder.CreateCompilation` injects a synthetic global-using tree when enabled. Closes the 42% `GetSymbolInfo` null-resolution class (without this, `List<>`, `Dictionary<>` etc. emit CS0246 on every module). Follows INV-COMPFACT pattern.
  - **Constructor `Calls` edge.** `ExtractConstructorCallEdge` emits BOTH a type-level `References` edge (module-coupling signal) AND a method-level `Calls` edge to the `.ctor`. `find_references` on any constructor returns its construction sites.
  - **Field-initializer containing method.** `FindContainingMethodOrLocal` resolves a reference inside `static T _x = Bar()` / `T _x = Bar()` to the type's synthesized `.cctor` / first `.ctor` via `StaticConstructors` / `InstanceConstructors`.
  - **Property accessor context.** `FindContainingMethodOrLocal` returns the accessor `IMethodSymbol`; `GetMethodId` maps `AssociatedSymbol` to the property/event id so the emitted edge source matches the extracted graph node. Covers bodied accessors, expression-bodied properties, and indexer expression bodies.

  Pinned by `Handle_DeadCode_Response_IncludesExperimentalWarning` plus 26 extractor/analyzer tests in `RoslynExtractorTests` covering each closed FP class.

- **INV-DEADCODE-TRIAGE-002. Dead-code findings carry `sameClassConsumerCount`; `DeadCodeOptions.IncludeSameClassOnlyConsumers` opt-in surfaces symbols whose only consumers share the candidate's containing type.** Additive to INV-DEADCODE-TRIAGE-001. Default mode keeps the strict liveness filter — any symbol with an incoming non-Contains edge is excluded — so the count is `0` for every classic finding. When `IncludeSameClassOnlyConsumers=true`, the analyzer relaxes the filter to also surface symbols whose every incoming non-Contains reference originates from a member with the same `ParentId` (same containing type); the finding then reports the count plus a `Reason` of `"<scope><kind> with only same-class consumers (<N>)"`. Cross-class consumers (even one) suppress the relaxed surfacing — the symbol is genuinely consumed outside its declaring class and not a class-internal cleanup candidate. `IsLiveByOutgoingImplements` is split out of the legacy `HasIncomingReference` helper so the relaxation cannot accidentally surface interface implementers. Use case: class-level cleanup triage. A private field, property, or method whose only consumers are sibling members of the same class is a valid candidate for inlining or removal during a focused class-by-class pass, even though it is semantically alive. `SameClassConsumerCount` is always populated on the wire so consumers can sort/filter, even when the relaxation is off (returns `0` in classic mode). Pinned by `AnalysisToolsTests.DeadCode_DefaultMode_PrivateFieldWithSameClassConsumer_IsNotFlagged` (default filtering preserved), `DeadCode_RelaxedMode_PrivateFieldWithSameClassConsumer_IsFlaggedWithCount`, `DeadCode_RelaxedMode_PrivateFieldWithCrossClassConsumer_IsNotFlagged`, and `DeadCode_TrulyUnusedPrivateField_ReportsZeroSameClassConsumers`. LB-TRACK-20260515-015 / F2 atom of the 2026-05-19 plan.

## Invariant Introspection (v0.6.3, tree-walker added LB-FR-023)

- **INV-INVARIANT-001. Architectural invariants live across well-known repo conventions; the tool aggregates them at runtime.** `lifeblood_invariant_check` discovers source files dynamically via `IFileSystem` — `<root>/CLAUDE.md`, `<root>/AGENTS.md`, and any `<root>/docs/invariants/**.md` tree — parses each with `Internal.ClaudeMdInvariantParser`, caches per-file in `InvariantParseCache<T>` (timestamp-based invalidation), and aggregates results across all sources. Five authoring shapes recognised: A (`- **INV-X-N**: body`), B (`- **INV-X-N. Title.** Body`), C (`**INV-X-N: Title.** body` — bare bold paragraph, no bullet), D (`- **INV-X-N** (vX.Y.Z): body` — parenthesized version tag), E (`- **INV-X-N:** body` — colon inside the bold). Three modes via `IInvariantProvider`: `id` lookup (full body), `audit` (total + per-category breakdown + duplicate ids + parse warnings + every contributing source path in `SourcePaths[]`), `list` (id+title index, no bodies). Parser is a pure function; provider is a thin orchestrator over discovery + cache + parser — adding a new invariant source layout (YAML companion file, GitHub issue tracker, external governance DB) ships as a sibling provider reusing the cache. Duplicate ids declared across files are detected and surfaced. Pinned by `ClaudeMdInvariantParserTests`, `InvariantProviderAndHandlerTests`, `LifebloodClaudeMdSelfTests`, `InvariantParseCacheTests`. Closes LB-BUG-017 / LB-BUG-018 / LB-FR-023.

- **INV-PORT-HEALTH-COMPOSITE-001. `port_health` reports direct + inherited interface surface; liveness verdict is computed across the aggregate.** Pre-F3b, the analyzer counted only directly-declared members reached by outgoing `Contains` edges. Composite interfaces — types that inherit from one or more sub-interfaces and declare little or no surface themselves — appeared as `empty` even when their inherited contracts carried real load-bearing surface. F3b walks outgoing `EdgeKind.Inherits` edges transitively from the target type (the shared `Lifeblood.Domain.Graph.InterfaceInheritanceWalker`, also used by `authority_report` post-F3e), collecting every reachable interface's direct members (distinct by canonical id), and computes verdict + `liveMembers` + `live[]` / `dead[]` across the union of (direct ∪ inherited). Five new wire fields on `PortHealthReport`: `directMemberCount` (pre-F3b count, what this type contributes itself), `inheritedMemberCount` (distinct ids reachable through the inheritance closure), `aggregateMemberCount` (sum), `inheritedInterfaces[]` (canonical ids, sorted ordinal so the wire shape is deterministic), `isCompositeInterface` (true iff `inheritedMemberCount > 0`). `memberCount` retains its pre-F3b name as a backwards-compatible alias for `aggregateMemberCount` — older callers still get a verdict-relevant total without code change. Pinned by `PortHealthAnalyzerTests` (6 F3b fixtures: non-composite zero-inherited, composite with all-live inherited, composite mixed-live inherited, transitive grandparent walk distinct across closure, empty composite reports `empty`, composite with own direct members aggregates both surfaces). ## Authority Report + Forwarder Classifier (v0.6.7 P5, post-v0.7.7 F3e)

- **INV-AUTHORITY-COMPOSITE-001. `InterfaceUsage` rows on an authority report carry direct + inherited member surface; composite interface facades aggregate inherited contracts.** Pre-F3e, each per-interface row reported only the satisfied interface's directly-declared members (outgoing `Contains` edges from the interface itself). F3e reuses the shared `InterfaceInheritanceWalker` (also used by `port_health`'s F3b) to walk the satisfied interface's transitive `EdgeKind.Inherits` closure and sum each parent's direct member count. Five new wire fields on `InterfaceUsage`: `directMemberCount` (pre-F3e count, what the satisfied interface contributes itself), `inheritedMemberCount` (distinct member ids reachable through the inheritance closure), `aggregateMemberCount` (sum), `inheritedInterfaces[]` (canonical ids, sorted ordinal so the wire shape is deterministic), `isCompositeInterface` (true iff `inheritedMemberCount > 0`). `memberCount` retains its pre-F3e name as a backwards-compatible alias for `aggregateMemberCount`. Consumer counting also walks the aggregate: a caller of an inherited member counts as a consumer of the composite facade (it reaches the contract). Pinned by `AuthorityReporterTests.AuthorityReport_CompositeInterfaceFacade_AggregatesInheritedSurface`, `AuthorityReport_NonCompositeInterface_ReportsZeroInheritedSurface`, `AuthorityReport_CompositeInterfaceConsumers_CountAcrossAggregate`, `AuthorityReport_InterfaceTypeAsHost_FindsParentInterfacesPostF3c`, and `AuthorityReport_RealGraph_CompositeHost_AggregatesInheritedMembers` (real-graph end-to-end pin via the production extractor pipeline). LB-TRACK-20260519-022 / F3e atom of the 2026-05-19 plan.

- **INV-FORWARDER-001. Method body shape is classified at extraction time, recorded on `Properties["classification"]`.** Three categories: `PureForwarder` (single-statement / expression-bodied method whose body is exactly one invocation expression), `ThinWrapper` (≤ 5 statements containing exactly one invocation overall — null-guard-then-delegate, simple-cast-then-delegate), `RealLogic` (anything else). Abstract / partial / extern methods are not classified (no entry written) — there's no body shape to categorize. Heuristic, not semantic — recorded on the type's own member, not the call target — but stable enough that an authority report can compute a coarse forwarder ratio without a second walk. Detected by `RoslynSymbolExtractor.AttachMethodClassification` (Phase P5 / LB-FR-020). Pinned by `AuthorityReporterTests.Extractor_*`.

## Semantic Search Match Source

- **INV-SEARCH-MATCHKIND-001. `SearchResult.MatchKind` structurally reports which scoring bucket(s) drove the rank.** The reference adapter (`Lifeblood.Connectors.Mcp.LifebloodSemanticSearchProvider`) ranks symbols against three buckets — bare `Name`, `QualifiedName` (exclusive of Name per the bare-name guard), and persisted `xmlDocSummary`. Pre-fix the bucket signal lived only in the human-rendered `MatchSnippets` strings (`"name: …"` / `"qualifiedName: …"` / `"xmlDoc: …"`); callers who wanted to filter by source had to parse those strings. The first-hit-token trackers inside the adapter already knew which buckets fired — INV-SEARCH-MATCHKIND-001 lifts that to a typed `MatchKind` enum on `SearchResult`. Values: `Name`, `QualifiedName`, `XmlDoc` for single-bucket hits; `Multiple` when more than one bucket fired (e.g. token in both bare name and xmldoc summary, or qualified name and xmldoc summary). The enum is adapter-agnostic — future TypeScript / Python search adapters reuse the same taxonomy (their corpora carry the same conceptual buckets). Snippet strings are unchanged so existing renderers keep working; the structured field is purely additive. Pinned by `SemanticSearchTests.Search_*MatchKind*` (5 cases: name-only, qualifiedName-only-with-bare-name-guard, xmldoc-only, name+xmldoc Multiple, qualifiedName+xmldoc Multiple).

## Member Resolution (post-v0.7.2)

- **INV-RESOLVE-MEMBER-001. `lifeblood_resolve_member` is a type-scoped counterpart to `lifeblood_resolve_short_name`.** Where short-name resolution flattens every member matching a bare name across the entire graph (often 16+ hits on common names like `Dispose` / `Update`), `ResolveMember(graph, typeName, memberName, paramTypes?)` scopes to ONE specific containing type and returns the member surface on THAT type only. The `typeName` argument accepts canonical (`type:NS.T`), fully-qualified (`NS.T`), or bare short name (`T`); bare names dispatch through the short-name index. When the bare short name resolves to multiple types, `outcome = AmbiguousContainingType` with every candidate id returned for caller disambiguation — the resolver NEVER silently picks. The `paramTypes[]` argument filters method overloads by parameter signature (each entry is one fully-qualified parameter type); ignored for non-method members. Typed outcome enum: `Unique` / `MultipleMatches` / `NotFound` / `TypeNotFound` / `AmbiguousContainingType`. Port: `ISymbolResolver.ResolveMember` + `MemberResolutionResult`. Adapter: `LifebloodSymbolResolver.ResolveMember`. Pinned by `ResolveMemberTests` (12 cases covering every `ResolveMemberOutcome`). Closes the field-report 2026-05-11 P1 type-scoped-member ask.

## Rename Wire Shape (post-v0.7.8 LB-TRACK-20260524-025)

- **INV-RENAME-CROSS-PARTIAL-001. `lifeblood_rename` runs `Renamer.RenameSymbolAsync` at Solution scope and iterates every changed `Document`; cross-partial / cross-file / cross-asmdef usages of the renamed symbol are included in the response by construction, not by special-case branching.**

- **INV-RENAME-POINT-EDITS-001. `lifeblood_rename` emits one wire-level `TextEdit` per Roslyn-emitted `Document.GetTextChangesAsync` change; whole-file replacement is impossible by construction.** Pre-LB-TRACK-20260524-025 the adapter used `SourceText.GetTextChanges(oldText)` which does a brute text diff between two `SourceText` instances. When the pre/post Roslyn documents come from different `TextLoader` containers (workspace-loaded `oldText` vs Renamer-emitted `newText`) the two `SourceText` instances do not share an internal container, so the diff degenerates to a single change-everything `TextChange` covering the whole file body — caller saw `editCount: 1` with `startLine=1, endLine=lastLine, newText=full file body`. Diff and selective-apply became impossible; mechanical application would overwrite any concurrent local edits. Fix: switch to `Document.GetTextChangesAsync(oldDocument)` — Roslyn's Document-level diff surfaces the granular `TextChange`s the Renamer authored, not a brute text diff. Each `TextChange` is a narrow identifier-span replacement (often a minimal substring of the new identifier per Roslyn's minimal-diff guarantee — `Greeter` → `SimpleGreeter` emits `NewText = "Simple"`, not `"SimpleGreeter"`, at a one-column insertion point). One wire-level `TextEdit` per change is point-edit by construction. Wire shape unchanged otherwise — caller still sees `editCount` + `edits[].{FilePath, StartLine, StartColumn, EndLine, EndColumn, NewText}`. Pinned by `RenameWireShapeTests.Rename_SameFileMultiUseProperty_EmitsOneEditPerSite_NotWholeFile` + `Rename_SameFileMultiUseMethod_EmitsOneEditPerSite_NotWholeFile` + `Rename_PointEditNewText_ContainsOnlyTheNewIdentifier_NoFileBody` (asserts every edit's vertical span < totalLines/2, NewText length ≤ new-identifier length). `WriteSideIntegrationTests.Rename_GreeterType_ReturnsRealEdits` was relaxed to match the new minimal-diff contract (NewText is a substring of the new identifier, not the full identifier). Closes LB-TRACK-20260524-025.

## Enum Coverage (post-v0.7.3, post-v0.7.7 S4)

- **INV-ENUM-COVERAGE-001. `lifeblood_enum_coverage` returns per-member reference coverage for an enum type — `produced` / `consumedComparison` / `consumedSwitch` / `other` counts classified by parent syntax, plus convenience flags `isUnproduced` (declared + referenced as a consumer but never assigned) and `isUnreferenced` (zero references of any kind).**

- **INV-ENUM-COVERAGE-DISPATCH-TABLE-001. `enum_coverage` reports an additive `dispatchTableReferenceCount` for references that live inside a static-table-shaped initializer; recognition shares the `static_tables` classifier so there's one source of truth.** Pre-S4 the analyzer was purely syntactic — it classified an enum-member reference into Produced / Comparison / SwitchPattern / Other by parent syntax, with no awareness that some `Produced` sites are routing-table cells (`new Capability(Mode.A, HandleA)` in `static readonly Capability[] All = { ... }`) rather than genuine assignments. The blind spot prevented triaging "values that exist only as dispatch keys" from "values genuinely produced in app code". S4 adds `DispatchTableReferenceCount` to `EnumMemberCoverage` — ADDITIVE: every dispatch-table cell still increments its syntactic bucket (typically `ProducedCount`, since argument position is value-producing) AND increments this new counter. A row where `DispatchTableReferenceCount == TotalReferences` is a pure routing key; a row where `DispatchTableReferenceCount == 0 && ProducedCount > 0` is a normal assignment site. Recognition lives in `RoslynStaticTableExtractor.IsInsideStaticTableInitializer(model, node)` — walks syntax ancestors up to either an `EqualsValueClauseSyntax` (`= expr` form, fields + property setters) OR an `ArrowExpressionClauseSyntax` (`=> expr` form, expression-bodied static properties), verifies the enclosing declaration is a `static` field or property, then calls the same private `ClassifyContainer` the `static_tables` tool uses to decide if the initializer shape is `Array` / `CollectionExpression` / `ObjectCreation`. Both initializer shapes are recognised in parity with the static-table extractor's `TryGetInitializerExpression` (which also accepts both — a parity gap caught during S4 self-review). Single SSoT: any future container-shape extension on `static_tables` automatically widens what counts as a dispatch table here. Stops at any enclosing `StatementSyntax` / `AnonymousFunctionExpressionSyntax` so a reference inside a method body or lambda does not falsely match an enclosing field initializer (a lambda body inside `static readonly Func<Mode> F = () => Mode.A;` is its own scope — the lambda IS the dispatch-table cell, not its body). INSTANCE field initializers are excluded (the recognition requires the `StaticKeyword` modifier) so the predicate stays honest about what is and is not a static dispatch table. Pinned by `EnumCoverageTests` (8 S4 facts: object-creation rows count, regular production sites don't count, literal-array initializers count, switch arms don't count, expression-bodied static-property arrow initializers count, lambda bodies inside static initializers don't count, instance-field initializers don't count, dispatch-table-only-member triage scenario). LB-TRACK-20260515-014 / S4 atom of the 2026-05-19 plan.

## Test Impact (post-v0.7.3)

- **INV-TEST-IMPACT-001. `lifeblood_test_impact` reports which test classes transitively depend on a target symbol or file, classified by hop distance and grouped by containing type.** Pre-fix a caller asking "which tests prove that my change to X is safe?" had to pair `lifeblood_blast_radius` with manual test-method discovery (filter the affected list to test-bucket paths, walk back to containing types, compose `dotnet test --filter` strings by hand). The new tool does it in one call. Algorithm: BFS over INCOMING non-Contains edges with per-symbol minimum-distance tracking; first-seen wins because BFS explores in increasing-distance order. Each visited Method symbol is checked against the extractor-recorded `Properties["attributes"]` string — the test-case attribute set is `Test`, `TestCase`, `TestCaseSource`, `Theory`, `UnityTest`, `Fact` (NUnit + Unity Test Framework + xUnit). Lifecycle attributes (`SetUp`, `OneTimeSetUp`, `TearDown`, `OneTimeTearDown`, `UnitySetUp`, `UnityTearDown`) are intentionally excluded — they participate in test execution but are not the assertion-bearing methods a caller wants enumerated. Affected test methods are folded by their containing type (walked via `Symbol.ParentId` chain); per-class `minDistance` is the smallest distance across the class's affected methods, mapped to confidence Direct (1) / OneHop (2) / Transitive (3+). Wire shape: `target`, `targetKind` (Symbol or File), `totalTestMethodCount`, `directTestClassCount`, `affectedTestClassCount`, `affectedTestClasses[]` sorted by ascending distance then by qualified name for byte-stable output, plus `recommendedFilters[]` — pre-composed `FullyQualifiedName~<qualifiedName>` strings the caller pastes into `dotnet test --filter` without composing the syntax themselves. Disambiguation: a `target` value starting with a canonical-id prefix (`type:` / `method:` / `field:` / `property:` / `mod:` / `file:` / `ns:` / `namespace:`) routes through `ISymbolResolver`; otherwise the value is treated as a file path and every symbol declared in that file becomes a multi-source BFS start (single-pass analyzer; distance is the minimum over every file-side source). Lives in `Lifeblood.Analysis/TestImpactAnalyzer.cs` because the walk is pure graph read (INV-ANALYSIS-002) — no Roslyn compilation needed, separate from the write-side semantic tools. Pinned by `TestImpactAnalyzerTests` (9 facts: no-tests empty report, direct-caller Direct confidence, one-hop OneHop confidence, tests grouped by containing type, non-test methods excluded, lifecycle attributes excluded, recognizes UnityTest + xUnit Fact, recommended-filters in distance order, file-mode multi-source BFS). The test-case attribute set is duplicated relative to `UnityReachabilityAdapter`'s entry-point set; that's intentional — UnityReachability uses the broader set for dead-code dispatch-entrypoint detection, this analyzer needs only assertion-bearing methods. Consolidation belongs to a separate atom if the two policies ever diverge. Closes LB-TRACK-20260514-007.

## Path Bucket Classifier SSoT (post-v0.7.3)

- **INV-PATHBUCKET-SHARED-001. Path-prefix classification into `Production` / `Test` / `Editor` / `Generated` lives in one Domain-layer SSoT (`Lifeblood.Domain.PathClassification.PathBucketClassifier`); every consumer forwards through it.** Pre-fix three classifiers had drifted in three places: `LifebloodDeadCodeAnalyzer.ClassifyBucket` (Connectors.Mcp), `LifebloodMcpProvider.ClassifyBucket` (Connectors.Mcp), and `CircularDependencyDetector.IsGeneratedOrStaticAnalysisPath` (Analysis). Each implemented its own segment-walk with subtly different precedence rules (e.g. one walked `Editor/` ahead of `Tests/`, another did the reverse) — exactly the silent-drift class the SSoT pattern exists to prevent. The Domain-layer classifier is a pure function over a file-path string: walks path segments (not substrings, so `Editor` matches `Editor/Foo.cs` but not `MyEditor.cs`), applies precedence `Generated → Test → Editor → Production` (most-authoritative signal wins; Tests-under-Editor reads as Test fixture by design), and returns one of four enum values. Domain layer is the correct home — the rule is data-domain (path strings, not Roslyn semantics or adapter wiring) and has zero outbound deps. The `PathBucket` enum integer values mirror the Connector-layer `DeadCodeBucket` enum so the two stay byte-equal at the wire — pinned by `PathBucketParityTests`. All three former classifiers now forward to `PathBucketClassifier.Classify`; the legacy method bodies stay (one-line `=> PathBucketClassifier.Classify(...)`) so the caller surface is byte-stable but the implementation is single-rooted.
